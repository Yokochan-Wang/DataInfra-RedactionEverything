# 名词解释（小白版）

配套阅读：`实验方案.md`、`../模型调研-laya-multilingual.md`。
写法：**术语（白话解释）**。

---

## 一、模型是什么

- **模型**（一个"输入文字 → 输出结果"的程序。它内部是一堆数字，这些数字是从大量数据里"学"出来的——好比练出来的直觉，不是人能读懂的规则）
- **参数 / 参数量**（模型内部可调的数字个数。322M = 3.22 亿个；0.6B = 6 亿个。数字越多通常越聪明，但也越慢、越吃硬件）
- **大模型 / 小模型**（按参数量粗略分。你的 HaS Text 是 0.6B（6 亿），远端 qwen3.8-27b 是 27B（270 亿））
- **本地模型**（模型跑在你自己这台电脑上）
- **远端模型 / 远程模型**（模型跑在别人的服务器上，你的电脑通过网络把文字发过去、等结果回来）
- **推理**（模型用已经学好的数字算一次答案的过程。反义词是"训练"）
- **训练**（从零开始教模型）
- **微调**（在已经训练好的模型上，用你自己的数据再教一点，让它更懂你的场景）
- **零样本**（完全不教，直接拿来用。官方说 laya 在零样本下某些任务接近瞎猜）

## 二、文字怎么变成模型能吃的数字

- **token / 词元**（模型不认识"字"，只认识 token。中文约 1 个汉字 ≈ 1 个 token，英文 1 个词 ≈ 1-2 个。token 是模型的"字数单位"，也是限长和收费的单位）
- **分词器**（把一句话切成 token 的那个工具）
- **词表**（模型认识的 token 清单。256k 词表 = 认识 25.6 万个 token）
- **上下文长度**（模型一次最多能看多少 token。laya 是 1024，大约 1000 个汉字；超过的部分会被砍掉）
- **截断**（超长被砍掉这件事。laya 是从右往左砍即丢掉后面的内容，而且不报错——所以你可能不知道哪些内容根本没被看到）

## 三、模型输出的是什么

- **概率**（0 到 1 之间的数，表示有多大把握。0.93 = 93%）
- **logits**（模型还没换算成概率之前的原始分数，可能是 -7.3 这种没意义的数）
- **softmax**（把一堆原始分数换算成加起来等于 1 的概率的那个公式）
- **温度**（调节概率极端程度的旋钮。小于 1 会让概率更极端——0.24 被吹成 0.99；大于 1 会让概率更平均）
- **标定 / 未标定**（判断"模型说的 90% 是不是真的 90%"。未标定 = 模型说自己很有把握，但实际没那么准。官方明说 laya 未标定）
- **置信度**（模型自己报告的"我有多确定"。注意它不等于准确率，未标定时尤其不能信）
- **决策模型**（只负责"选一个"的模型，像做选择题，不会写作文）
- **生成式模型**（会一个字一个字写出来的模型，像 ChatGPT。laya 不是这种）
- **编码器**（把文字读进去、理解成一组数字的那部分）
- **解码器**（把数字写回成文字的那部分。laya 没有解码器，所以它写不出任何文字）
- **分类 / 判别**（只判断"属于哪一类"或"是/否"，不生成新文字）

## 四、laya 专用的词

- **noul**（laya 三种题型里的第 3 种 = 是 / 否题。输出"成立"的概率）
- **choice**（选择题：从你给的几个选项里选一个）
- **score**（打分题：从你给的有序等级里打分，比如"不敏感 / 一般 / 敏感 / 极敏感"）
- **instructions**（指令：你用一句话告诉它"这道题问什么"）
- **criteria**（选项 / 候选答案清单。laya 只能在这些里面选，不能自己发明答案）
- **state**（输入状态：你要它判断的那段文本）
- **marker / [MASK]**（一个特殊占位符。laya 会在每个选项前面插一个 [MASK]，然后在那个位置给每个选项打分）
- **决策头**（模型末端"负责下结论"的那一小层网络）
- **act / escalate**（行动 / 升级：laya 额外的一个头，输出"我直接答"和"建议转给更强模型"的概率）
- **act_probability**（上面那个"我直接答"的概率。这是它唯一独立于答案概率的信号）
- **mmBERT / ModernBERT**（laya 用的"文字理解底座"的名字，一种编码器架构）
- **路由**（laya 自带功能：先看这段文字是什么语言，再决定用哪个版本的模型）
- **脚本检测**（判断文字是汉字、拉丁字母、阿拉伯文……这个不需要 AI，是查 Unicode 编码表，所以是精确的）

## 五、评价好坏用的词

- **真值 / 标准答案**（人工标好的"这段文字里到底有哪些敏感信息"）
- **标注**（人工标出答案这件事）
- **语料**（一批给实验用的文档）
- **黄金语料**（人工核对过标准答案的那批文档。你仓库里 e2e/corpus/ 就是）
- **召回**（该找到的，找到了多少比例。真值里有 100 个身份证号，找到 98 个，召回 = 98%。**召回低 = 漏检 = 泄漏**）
- **漏检**（真的有敏感信息，但没找到）
- **精确率**（你报出来的，有多少是对的。报了 100 个，其中 90 个真的是敏感信息，精确率 = 90%。**精确率低 = 误报多 = 把没关系的东西也打码了**）
- **误报**（本来不是敏感信息，被判成敏感了）
- **准确率**（一共判对多少比例。**这个指标会骗人**：如果 90% 的句子本来就不敏感，一个"全说不敏感"的傻瓜模型准确率也有 90%）
- **AUC**（衡量排序能力的 0-1 分。0.5 = 瞎猜，1.0 = 完美。问的是"laya 给的分能把真敏感的排在前面吗"）
- **门槛 / 阈值**（你自己定的及格线，比如"概率 ≥ 0.8 才算敏感"）
- **召回门**（硬性规定"召回必须 100%"，否则不允许上线。你项目里 identity 类就是这个硬门槛）
- **域**（业务领域。你的域是"中文法律 / 医疗 / 金融文档脱敏"。**模型在别的域准，不代表在你的域准**）
- **泛化**（在没见过的数据上也能表现好）
- **极性**（"概率高"到底代表"是"还是"否"。搞反了整张成绩单就全反了）
- **正负对照**（故意喂一句一定"是"和一句一定"否"的话，先确认极性没反）
- **置信区间 / Wilson 上界**（因为样本少，结论有不确定性。测 100 句全对，只能说"真实漏检率最坏也就 3%"（95% 把握），不能说"就是 0%"。这就是"能否决、不能证明"）
- **统计功效**（样本量够不够支撑你得出的结论）

## 六、你项目里的名词

- **NER / 命名实体识别**（从文字里找出人名、身份证号、地址这类"实体"并标出位置。本项目文本流的核心任务）
- **实体**（一段有特定意义的文字，比如"张三"是人名实体）
- **脱敏 / 打码 / 红框**（把敏感信息遮掉或替换成占位符。你输出里看到的 <地址[001]> 就是）
- **span / 偏移 / start / end**（实体在原文里的起止位置，即第几个字符到第几个字符。**打码必须知道位置**——这就是 laya 不行的原因：它只会说"是 / 否"，不会说"在第 15 到 17 字"）
- **OCR / 光学字符识别**（把图片、扫描件里的文字认出来变成文本）
- **管线 / 流水线**（一整套处理流程，比如"上传 → 抽文字 → 找实体 → 打码 → 输出"）
- **chunk / 分块**（长文档切成一小块一小块分别送给模型，因为模型一次看不了那么多）
- **chunk 上限**（你这块配置最多 12 块、每块 1600 字符 ⇒ 一篇文档最多处理 19,200 字符）
- **剪枝**（先砍掉一部分内容，只把可能重要的送给模型，省时间省成本）
- **排序**（不砍，只换顺序，把可能重要的排前面，让它在容量上限内先被处理）
- **skip 门**（判断"整篇都没敏感信息"就直接跳过 NER，省一次调用）
- **cascade / 级联**（快的模型先筛，不确定的再交给慢的强模型复核）
- **自洽性 / 一致性**（同样的问题问两遍或换个问法，答案应该一样。变了就说明不可靠）
- **批处理 / batch**（把多条内容攒在一起一次算完，比一条一条算快。laya 的 batch 是"同一段文字 × 多个问题"）

## 七、接口与工程词

- **接口 / API**（程序之间说话的约定方式）
- **OpenAI 兼容接口**（按 OpenAI 那套格式说话的接口，好处是谁都能换。本项目现在就用这个）
- **/chat/completions**（OpenAI 兼容接口里最常用的那个"对话地址"。**laya 没有这个**，它是 Python 包，不是网络服务）
- **base_url / 接口地址**（服务在哪，比如 http://127.0.0.1:8080/v1）
- **API Key**（访问远端服务的密码 / 钥匙）
- **llama-server / vLLM**（两个把模型变成网络服务的软件，这样别的程序才能通过 HTTP 调它）
- **GGUF / Q4**（把模型压缩变小的文件格式 / 压到 4 位精度。压缩后更省显存，质量略降）
- **venv / 虚拟环境**（给一个项目单独隔离的 Python 环境，免得不同项目的依赖打架）
- **pip**（Python 的装包工具，类似手机的应用商店）
- **torch / PyTorch**（跑深度学习模型的底层引擎。laya 必须靠它才能跑，它很大，约 2.5GB）
- **transformers**（HuggingFace 出的模型工具箱库）
- **CPU**（普通处理器，慢但通用）
- **GPU / 显卡**（算矩阵特别快，适合跑模型）
- **CUDA**（NVIDIA 显卡的并行计算框架）
- **显存 / VRAM**（显卡自己的内存。你的 RTX 3060 有 12GB）
- **bf16 / fp16 / fp32**（数字的精度。fp32 最准最占地方，bf16 / fp16 体积减半）
- **Docker**（把软件和它的环境一起打包成"集装箱"，换台机器也能一样跑）
- **WSL**（在 Windows 里跑一个 Linux 子系统）
- **SQLite**（一种单文件数据库。你项目的 file_store.sqlite3 就是）
- **.env / 环境变量**（配置文件，放地址、密码这类设置）
- **SSRF / 白名单 allowlist**（安全防护。白名单 = 只允许访问名单上的地址；SSRF = 攻击者骗服务器去访问内网地址）
- **后端 / 前端**（后端 = 服务器上干活的程序，Python；前端 = 你在浏览器里看到的界面，React）
- **正则表达式 / regex**（一种精确的文本匹配规则，比如"18 位数字"）
- **确定性**（同样输入必得同样输出，不会看心情。正则和查表是确定性的；AI 模型不是）
- **启发式**（经验规则，不是严格算法，可能不准但够用）
- **pin 版本**（把依赖锁定在某个具体版本号上，比如 laya==0.3.5，免得升级后结果变了无法对比）
- **3 个数量级**（10 倍 = 1 个数量级。3 个数量级 = 1000 倍）

## 八、你项目里的敏感实体类型

- **PERSON**（人名）
- **ID_CARD**（身份证号）
- **BANK_CARD**（银行卡号）
- **PHONE**（手机号）
- **EMAIL**（邮箱）
- **ADDRESS**（地址）
- **INSTITUTION_NAME**（机构名，比如公司名）
- **identity 类**（你的项目术语 = 姓名 + 身份证 + 手机 + 银行卡。**漏检不可接受，召回必须 100%**）
- **standard 类**（邮箱 + 地址 + 机构名。召回 ≥ 85%）
- **Luhn 校验 / 校验和**（银行卡号自带的数学校验规则。你的代码注释特意说不能用它，因为你的真值里有些号本来就不满足校验和）

## 九、我在数据里用的统计词

- **中位数**（把所有数字从小到大排，正中间那个。比平均数更抗极端值）
- **p90 / p99 / 第 90、99 百分位**（90% / 99% 的样本都不超过这个值。用来看"最差的那批有多差"）
- **字符数**（一个汉字算 1 个字符，一个英文字母也算 1 个）

## 十、把这些词套回我的结论

**结论一：laya 不能替换 NER 模型。**
laya 是**决策模型**（只会"是 / 否"和"选一个"），没有**解码器**（写不出文字），
它的输出是**概率**（0-1 的数），所以给不出 **span / 偏移**（实体在第几个字符到第几个字符）。
而你的**管线**要靠**偏移**才能**打码**。差的是**任务类型**，不是模型大小。

**结论二：用它做剪枝提效，在你的真实数据上不成立。**
我量了 112 份**真实文档**（**真值**数据集之外的、你实际上传的东西）：**字符数**中位数只有 830。
你的管线**chunk 上限**是 19,200 字符（12 块 × 1600），所以**中位文档本来就只要 1 块 = 1 次调用**。
**剪枝**（砍掉一部分内容）没法把"1 次调用"变成"0 次"，所以省不下时间；
反而要额外付出 laya 自己的**推理**开销（每份约 +240 毫秒）。**净亏。**

**结论三：唯一有价值的方向是反过来——救那 1 份 169 KB 的长文档。**
它现在只被处理了 11%（因为撞到 **chunk 上限**），属于**召回**（该找到的没找到）受损。
那里需要**排序**（不砍，只把重要的排前面）或扩预算，**不是剪枝**。

**结论四：真要用，必须先过"召回门"。**
你的 **identity 类**（姓名 / 身份证 / 手机 / 银行卡）**召回必须 100%**，这是硬门槛。
laya 官方说自己的概率**未标定**（说自己 90% 把握时其实没那么准），
而且某些任务**零样本**接近随机，所以**不能假设它能用**，必须先在你的**黄金语料**上测。
测的方法就是 `实验方案.md`：先做**正负对照**确认**极性**，再用**真值**算**召回**，
用**合成增强**把样本量提上去，最后用**置信区间**说明残余风险。
