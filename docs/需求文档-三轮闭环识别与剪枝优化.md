# 三轮闭环识别与剪枝优化需求文档

版本：v0.1（草案）  
状态：待评审  
适用范围：单文件处理、批量处理；文本、OCR 文本块与视觉目标识别链路

## 1. 背景与问题

当前平台已具备 OCR、HaS Text 语义 NER、视觉特征定位、规则兜底、人工复核与导出能力，但单轮识别仍可能受到以下因素影响：

- OCR 噪声、断行、表格布局和印章遮挡导致文本实体漏检；
- 低置信度候选需要结合邻近上下文才能判断；
- 文本链路与视觉链路可能重复输出同一对象，或对同一区域给出不同标签；
- 对已稳定识别区域重复调用模型，增加时延、显存和并发压力。

本需求拟引入“识别—汇总—剪枝—再识别—验证”的三轮闭环，通过跨轮结果积累提升召回与一致性，并利用已识别文字块索引减少后续监测范围。

## 2. 目标与非目标

### 2.1 目标

1. 提升复杂文档、扫描件、混排文本和视觉目标的敏感信息召回率，重点保障 identity 类实体不漏检。
2. 对跨轮候选进行去重、冲突消解、置信度融合和坐标统一，形成可审计的最终实体集。
3. 通过安全剪枝减少后续轮次的输入块数、Token 数和模型调用量，控制整体时延。
4. 保持现有人工复核、脱敏渲染、批量任务和导出接口兼容，可通过特性开关灰度发布。

### 2.2 非目标

- 本期不更换 OCR、NER 或视觉基础模型；
- 本期不改变已有实体类型定义、行业 Schema 和脱敏动作语义；
- 本期不以“自动确认”替代人工复核，三轮结果仍须遵循现有权限和确认流程。

## 3. 术语与核心原则

- **识别块**：OCR 输出的文字块、原生文本片段或视觉检测框，包含文本/图像坐标、页码、来源和质量信息。
- **候选实体**：某一轮识别出的待融合结果，至少包含实体类型、文本值或视觉标签、位置、置信度和来源。
- **硬剪枝**：后续轮次完全跳过已确认且稳定的区域。仅适用于高置信度、边界清晰、无冲突的候选。
- **软剪枝**：保留占位符、坐标和有限上下文，但不重复执行完整识别。适用于低置信度或需要上下文判断的候选。
- **保护区**：已确认的实体区域及其必要的上下文窗口，后续轮次不得覆盖或生成互相冲突的结果，除非触发复核条件。

核心原则：**先保召回，再做加速；先保留证据，再做脱敏。** 任何剪枝都必须可解释、可回滚、可审计。

## 4. 用户故事

| 角色 | 用户故事 | 验收要点 |
|---|---|---|
| 普通用户/操作员 | 上传文件后，系统自动完成最多三轮识别并给出更完整的实体清单 | 不需要额外操作；任务状态可见 |
| 审核员 | 查看每个候选来自哪一轮、为什么保留或剪枝 | 可展开识别轨迹和证据块 |
| 管理员 | 按行业或任务类型配置轮次、阈值和剪枝策略 | 配置有权限控制、默认值安全 |
| 运维/研发 | 判断质量提升是否值得性能成本 | 有每轮耗时、块数、Token、召回和冲突指标 |

## 5. 整体流程

一次任务最多执行三轮，允许因收敛条件提前结束：

1. **第 1 轮：全量粗识别**  
   在完整文本/OCR 块和启用的视觉范围内执行现有识别链路，目标是建立高覆盖率候选集。
2. **候选标准化与融合**  
   统一页码、坐标系、字符偏移和来源；对同一位置或同一文本的候选去重，保留候选证据。
3. **剪枝索引生成**  
   将候选划分为硬剪枝、软剪枝、待复检和未覆盖区域，并生成下一轮输入。
4. **第 2 轮：残余与重点复检**  
   重点扫描未识别块、低置信度块、OCR 质量差的块、候选边界邻域，以及 identity/行业专项高风险类型。
5. **第 3 轮：终检与边界验证**  
   对仍未收敛区域、跨块/跨行边界、类型冲突和视觉遮挡区域进行最终验证，可叠加规则校验和局部上下文。
6. **终止判定与输出**  
   满足收敛条件即停止；否则最多完成三轮。输出最终实体集、剪枝统计、识别轨迹和质量指标，交由现有复核与脱敏流程。

## 6. 功能需求

### FR-01 三轮闭环编排

- 新增可配置的闭环编排器，默认 `max_rounds=3`，兼容单轮模式。
- 每轮必须记录开始/结束时间、输入块数、输出候选数、模型调用数、Token 数、错误和终止原因。
- 轮次失败时支持按轮重试；重试必须幂等，不得重复写入候选或污染剪枝索引。
- 任务重启或进程恢复后，可从最近一个已落盘轮次继续。

### FR-02 候选标准化、去重与合并

- 候选至少包含：`candidate_id`、`round_no`、`entity_type`、`text/value`、`page_no`、`bbox` 或字符区间、`source`、`confidence`、`status`、`evidence_block_ids`。
- 支持字符重叠、IoU、邻接距离和规范化文本四类匹配信号。
- 同类型同位置候选合并为一个实体；不同类型冲突时进入冲突队列，不得静默覆盖。
- 同一实体跨轮出现时保留版本链，记录置信度变化和最终采用原因。
- 坐标必须可映射回原始页面/原始文本，确保脱敏渲染与人工复核定位准确。

### FR-03 安全剪枝策略

剪枝决策按“候选状态 + 识别质量 + 风险等级”计算：

- **硬剪枝条件**：置信度达到配置阈值、至少两类证据一致（如 NER+规则、OCR+NER、文本+视觉）、边界清晰、无冲突、非跨块边界。
- **软剪枝条件**：单一模型命中、置信度中等、OCR 质量一般、实体位于表格/印章/断行附近，或类型属于高风险专项。
- **不得剪枝条件**：identity 类低置信度候选、视觉遮挡区、页眉页脚不稳定区、候选跨行/跨块、候选与其他实体重叠、上一轮发生模型异常。
- 硬剪枝区域可从下一轮完整输入中移除；软剪枝区域需保留占位符（例如 `<PROTECTED_ENTITY_12>`）、原坐标和前后文窗口。
- 默认保留候选前后各 1 个文字块或可配置的字符窗口；窗口内不得再次生成与保护区重叠的结果，除非进入复检队列。
- 剪枝索引必须支持回滚：发现新候选与保护区相邻或冲突时，自动解除相关区域剪枝并重新送检。

### FR-04 分轮识别策略

- 第 1 轮：执行当前 Schema 中全部启用的文本/OCR/视觉识别项。
- 第 2 轮：默认扫描残余区域，并提高低置信度、identity 类、行业专项和 OCR 低质量区域的优先级。
- 第 3 轮：默认只扫描未收敛区域、实体边界邻域、跨块组合、冲突候选和视觉遮挡区域。
- 每轮允许指定模型、提示词、规则集、超时和并发上限；未配置时继承现有默认值。
- 可按文件类型、行业 Schema、页数和历史质量动态选择是否启用第 2/3 轮，但不得绕过 identity 类终检。

### FR-05 收敛与终止

满足任一条件即可提前结束：

- 本轮无新增候选，且无待复检/冲突区域；
- 新增候选数低于阈值，且新增候选均为低风险或重复候选；
- 所有 identity 类目标已达到策略要求，并完成边界验证；
- 达到最大轮次、任务超时或资源保护阈值。

终止原因必须展示在任务详情和审计日志中。

### FR-06 人工复核与解释

- 实体清单展示 `round_no`、来源链路、置信度、剪枝类型和合并说明。
- 审核员可查看原始证据块、前后文窗口和跨轮变化。
- 用户取消某候选时，系统可将该区域标记为“人工排除”，后续轮次不可重新加入，除非用户主动恢复。
- 用户手工新增或调整实体后，需重新计算相邻剪枝区域，避免覆盖人工修改。

### FR-07 结果、审计与可观测性

- 现有脱敏渲染只消费最终实体集；中间轮次结果仅用于审计、复核和质量分析。
- 任务日志不得记录未经保护的敏感原文；证据引用使用内部 ID，原文展示遵循现有权限。
- 指标至少包括：每轮候选数/新增数/重复数/冲突数、硬/软剪枝块数、剩余块数、Token 减少率、模型耗时、最终召回/精确率。
- 支持按文件类型、行业、实体类型和模型版本聚合查询。

## 7. 配置项（建议默认值）

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| `closed_loop_enabled` | `true`（灰度阶段按租户关闭） | 是否启用闭环 |
| `max_rounds` | `3` | 最大识别轮次 |
| `hard_prune_confidence` | `0.95` | 硬剪枝最低置信度，需结合证据一致性 |
| `soft_prune_confidence` | `0.75` | 软剪枝最低置信度 |
| `boundary_context_blocks` | `1` | 边界上下文块数量 |
| `min_new_candidates_to_continue` | `1` | 新增候选小于该值时可提前终止 |
| `identity_final_check` | `true` | identity 类强制终检 |
| `max_round_latency_ratio` | `1.8` | 相对单轮基线的时延保护阈值 |

上述数值为初始建议，需通过黄金语料和生产抽样校准，不得直接视为最终验收值。

## 8. 数据与接口变更

### 8.1 任务配置

在现有识别任务配置中增加：

```json
{
  "closed_loop": {
    "enabled": true,
    "max_rounds": 3,
    "pruning_mode": "safe",
    "hard_prune_confidence": 0.95,
    "soft_prune_confidence": 0.75,
    "identity_final_check": true
  }
}
```

### 8.2 任务状态

增加可选状态或进度字段：`recognizing_round_1`、`recognizing_round_2`、`recognizing_round_3`、`merging_candidates`、`validating_boundaries`。不改变现有成功、失败、取消和待复核终态。

### 8.3 识别结果

结果响应增加 `round_summary`、`pruning_summary`、`candidate_lineage` 和 `quality_summary` 字段；旧客户端忽略新增字段即可正常工作。

## 9. 质量与性能验收标准

以现有行业黄金语料和线上抽样为基线，至少满足：

- identity 类召回率保持 **100%**，不得因剪枝下降；
- standard 类召回率达到 **≥95%** 或较当前基线提升至少 5 个百分点；
- 实体类型正确率不低于现有基线，冲突候选不得静默丢弃；
- 脱敏后的漏遮率为 0；过度脱敏率较单轮基线增加不超过 2 个百分点；
- 第 2、3 轮平均输入块数较全量输入减少至少 40%；
- P95 端到端时延不超过单轮基线的 1.8 倍；大文档任务内存峰值增幅不超过 20%；
- 同一文件、同一配置重复运行三次，最终实体集合和坐标结果一致；
- 任一最终实体均可追溯至至少一个识别轮次和证据块；
- 关闭 `closed_loop_enabled` 后，现有单轮行为和接口保持兼容。

## 10. 测试要求

1. **单元测试**：坐标归一化、字符重叠/IoU 去重、候选合并、冲突排序、硬/软剪枝判定、收敛判定。
2. **回归测试**：法律、医疗、金融、政务黄金语料；重点覆盖 identity、跨行实体、表格、印章遮挡和视觉目标。
3. **对比测试**：单轮与三轮在召回、精确率、过度脱敏、时延、Token 和显存上的对比。
4. **故障测试**：OCR/NER/视觉服务超时、单轮失败、任务重启、重复提交、剪枝回滚、模型版本变化。
5. **并发测试**：多租户、多文件并发下剪枝索引、owner_id、模型上下文和审计记录不串租户。
6. **端到端测试**：上传 → 三轮识别 → 人工复核 → 脱敏 → 导出，验证导出文件与审计报告完整。

## 11. 发布计划

### 阶段一：离线验证

- 完成编排器、候选融合和剪枝纯函数；
- 在黄金语料上对比单轮/三轮，校准阈值；
- 默认关闭线上自动启用，仅输出影子指标。

### 阶段二：灰度发布

- 按租户或行业 Schema 开启；
- 先启用软剪枝，观察漏检、冲突和时延；
- 通过质量门槛后再启用高置信度硬剪枝。

### 阶段三：默认启用

- 保留单轮回退开关；
- 建立每周质量回顾和模型/规则版本对比；
- 将黄金语料门槛纳入 CI，任何 identity 召回下降即阻断发布。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 过度硬剪枝导致上下文丢失 | 漏检、错分 | 默认安全模式；identity 和边界区域禁止硬剪枝；支持回滚 |
| 三轮模型调用增加时延 | 用户等待变长 | 残余区域优先、早停、缓存、并发闸门和时延保护 |
| 多链路候选冲突 | 错误脱敏或人工负担增加 | 保留冲突状态，按证据加权，不静默覆盖 |
| 中间结果含敏感原文 | 审计泄露 | 最小化日志；证据 ID 化；沿用租户和角色权限 |
| 模型版本变化造成阈值失效 | 质量波动 | 版本化阈值、黄金语料回归和灰度开关 |

## 13. 待评审问题

- 是否将“最多三轮”固定为产品默认，还是按文件类型动态选择？
- 是否允许管理员为行业 Schema 单独配置硬剪枝阈值？
- 视觉目标是否与文字块共用剪枝索引，还是维持独立的视觉复检队列？
- 质量目标中的 standard 类提升幅度和时延上限，是否符合当前硬件与客户 SLA？
- 是否需要将每轮详情在前端默认展开，还是仅在高级审计模式展示？
