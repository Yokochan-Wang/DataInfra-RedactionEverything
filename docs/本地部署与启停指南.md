# 本地部署与启停指南（Windows 单栈）

本文面向本机日常使用。整套服务跑在 Windows 上，不依赖 WSL、不依赖 Docker。

> **当前生效的是第十节的模式**：NER 走远端 4090（qwen3.8-27b），OCR 与视觉链关闭，只用两个终端命令行启动。
> 第一到第九节描述的是本机 3060 单栈（8080 本地 llama-server + 8082 本地 OCR），需要时按第十节末尾的方法切回。

## 一、由哪些进程组成

| 端口 | 服务 | 实际进程 | 说明 |
| --- | --- | --- | --- |
| 3000 | 前端 | node + vite 6.4.2 | 浏览器访问入口 http://localhost:3000 |
| 8000 | 后端 | .venv python + uvicorn | FastAPI，接口文档 http://localhost:8000/docs |
| 8080 | 文本 NER | llama-server.exe（CUDA 版） | HaS Text 0.6B Q4 GGUF |
| 8082 | OCR | .venv python + ocr_server.py | PP-StructureV3，Paddle 3.3.0 GPU |

配置入口只有一个：根目录的 `.env`。四个进程共用它。后端会自己读根 `.env`（`app/core/config.py`
的 `env_file` 同时挂了 `backend/.env` 和根 `.env`，后者覆盖前者，真实环境变量优先级最高），
所以手动命令行启动不需要先把 `.env` 注入 shell。`backend/.env` 本机不存在，这是设计如此，不要新建。

## 二、日常启停

### 方式 A：双击批处理（推荐）

| 脚本 | 作用 |
| --- | --- |
| `start-app.bat` | 启动全部四个服务，窗口保持打开并滚动日志 |
| `stop-app.bat` | 停止全部服务 |
| `status-app.bat` | 查看四个服务在线状态与显存占用 |

启动窗口内按 `Ctrl+C`，或直接关掉该窗口，都会停止服务（窗口正常退出时会自动补跑一次停止）。
若强关窗口后担心有残留，再双击一次 `stop-app.bat` 兜底即可：它按端口占用和命令行特征（HaS 模型
名、本仓库脚本路径）双重识别进程，不会误伤机器上其他 python 或 llama-server。

### 方式 B：命令行

```powershell
npm run dev:local      # 启动
npm run status:local   # 查看状态
npm run stop:local     # 停止
npm run model:has      # 校验/补下 NER 模型权重
```

要求 Node 24。本机 Node 是便携版，若报 `node 不是内部或外部命令`：

```powershell
$env:PATH = "C:\Users\zkjg\AppData\Local\Programs\node-v24.19.0-win-x64;$env:PATH"
```

批处理里已硬编码该路径，所以双击方式不受影响。

- 之后热启动：约 25 秒，看到 `[stack] 全部就绪` 即可打开前端。

## 六、显存不够时怎么选

本机是 RTX 3060 12GB。当前 NER + OCR 约占 1.3GB，运行正常。

- `LOCATE_ANYTHING_ENABLED=0`：关闭 LocateAnything-3B 视觉 grounding。印章、指纹、手写签名这类
  图形实体识别不可用；表格、文档、扫描件里的文字类脱敏不受影响。
- `OCR_VL_ENABLED=0`：关闭 PaddleOCR-VL。OCR 服务此时只提供 `/structure`，直接请求 `/ocr` 会返回
  503，这是设计行为不是故障。
- 两者同时打开需要额外 8GB 以上显存，12GB 卡放不下，会 OOM。

只想跑文本链路、不加载 OCR 模型时，启动前设 `LOCAL_OCR_ENABLED=0`：

```powershell
$env:LOCAL_OCR_ENABLED = "0"; npm run dev:local
```

此时图片/PDF/Word 识别不可用，文本脱敏照常。

启动器还支持 `OCR_PORT`、`BACKEND_PORT`、`FRONTEND_PORT`、`WINDOWS_PYTHON`、`WINDOWS_VENV_DIR`
覆盖默认值。

## 九、常见问题

端口被占用：启动器会直接报「端口 xxxx（label）已被占用。请先双击 stop-app.bat……」。先跑一次
`stop-app.bat` 再启动。

改代码不生效：uvicorn 未开热重载，需 `stop-app.bat` 后重新 `start-app.bat`。

登录失败「Authentication session was not established.」（或写接口 403 Missing CSRF token）：
纯 HTTP 访问时 cookie 带 Secure 会被浏览器静默丢弃。根 `.env` 设 `COOKIE_SECURE=0` 后重启后端；
HTTPS 部署保持 1。

想看接口清单：http://localhost:8000/docs 。

`GET /api/v1/files` 的 `page_size` 上限是 100，超出返回 422。

删除文件要真正清磁盘需带 `?purge=true`，否则只是进回收站。

## 十、当前运行模式：远端 4090 + 不启 OCR（纯命令行）

根目录 `.env` 已切成这个模式。后端现在会自己读根 `.env`（`config.py` 的 `env_file` 同时挂了
`backend/.env` 与根 `.env`，后者覆盖前者，真实环境变量优先级仍最高），所以启动只要两行，
不需要 `.env` 加载器，也不需要任何 `$env:` 覆盖。

已实测：`has_ner = online (qwen3.8-27b, remote-gpu)`，NER 单请求 1.1s，实体识别正确；OCR 全程不被调用。

> 先看清提示符。`PS C:\...>` 是 **PowerShell**，`C:\...>`（没有 `PS`）才是 **cmd.exe**，两边语法
> 不通用：`cd /d`、`set PATH=...;%PATH%` 属于 cmd，`$env:X=...`、`Get-Content`、`| ForEach-Object`
> 属于 PowerShell，粘错一定报错。拿不准就在 PowerShell 里输 `cmd` 回车切进 cmd.exe，整段用 cmd 版。
>
> 另一个坑是一次别粘太多：**两行挤成一行**会让 PowerShell 把后半截当成 `cd` 的参数，于是报
> `找不到接受实际参数...的位置形式参数`。怕粘串行就用下面的单行版，一条命令就是完整一步。

### 终端 1：后端（8000）

PowerShell 单行版（整段只有一行，粘贴最安全）：

```powershell
cd C:\Work\WSY\DataInfra-RedactionEverything\backend; ..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

cmd.exe 版（`cd` 要带 `/d` 才能跨盘切目录，所以是两行）：

```bat
cd /d C:\Work\WSY\DataInfra-RedactionEverything\backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

在 `backend` 目录下跑不用设 `PYTHONPATH`，uvicorn 会把当前目录加进 `sys.path`。启动日志出现
`OCR service offline (expected at http://127.0.0.1:8082)` 是预期的，因为 OCR 故意没开。

### 终端 2：前端（3000）

另开一个窗口。PowerShell 单行版：

```powershell
$env:PATH = "C:\Users\zkjg\AppData\Local\Programs\node-v24.19.0-win-x64;" + $env:PATH; cd C:\Work\WSY\DataInfra-RedactionEverything\frontend; npm run dev -- --host 0.0.0.0 --port 3000
```

cmd.exe 版：

```bat
set PATH=C:\Users\zkjg\AppData\Local\Programs\node-v24.19.0-win-x64;%PATH%
cd /d C:\Work\WSY\DataInfra-RedactionEverything\frontend
npm run dev -- --host 0.0.0.0 --port 3000
```

是 `npm run dev`，不是 `npm dev run`。node 没装进系统 PATH，设 PATH 只对当前窗口有效，
每开一个新窗口都要重跑第一行。不带 `--host` 时 vite 只监听 IPv6 `::1`，`http://127.0.0.1:3000`
会连不上；加上 `--host 0.0.0.0` 后本机 `localhost` / `127.0.0.1` 与局域网都能访问。

### 当前 `.env` 的关键项

| 键 | 值 | 说明 |
| --- | --- | --- |
| `HAS_TEXT_RUNTIME` | `external` | 走远端 OpenAI 兼容服务，不带此值会去找本机 8080 |
| `HAS_TEXT_EXTERNAL_BASE_URL` | `http://4090-48g.zlattice.top:56666/v1` | 必须以 `/v1` 结尾 |
| `HAS_TEXT_MODEL_NAME` | `qwen3.8-27b` | 必须等于远端 `/v1/models` 里的 id，请求体 `model` 取的就是它 |
| `HAS_TEXT_API_KEY` | `sk-lm-...` | 自动作为 `Authorization: Bearer` 下发 |
| `HAS_LLAMACPP_BASE_URL` | 空 | 留空，避免 external 未命中时回退到 `127.0.0.1:8080` |
| `OCR_STRUCTURE_ENABLED` / `OCR_VL_ENABLED` | `0` | 后端不会去连 8082 |
| `LOCATE_ANYTHING_ENABLED` | `0` | 视觉特征链关闭 |
| `TEXT_ONLY_ENABLED` | `1` | 标记为纯文本模式（该项只被 `scripts/dev.mjs` 读取） |
| `HAS_NER_CONTEXT_TOKENS` | `8192` | 远端 `--max-model-len` / `--ctx-size` 必须 >= 此值 |

`external` 运行时会自动在请求里带 `reasoning_effort: "none"`，用于压制思考型模型的思维链占满
`max_tokens`；这正是选 `external` 而不是 `llamacpp` 的原因。响应 `content` 为空时会退回读
`reasoning_content`，所以思考型远端也不会直接吐白。

### 排障：远端 502 / 连不上

- 先 `Resolve-DnsName 4090-48g.zlattice.top`。如果解析到 `198.18.x.x` 这类地址，说明代理/TUN 的
  fake-IP 在劫持，请求根本没到 4090，网关会统一回 `502 Bad Gateway`（所有路径都 502，与 token
  无关）。关掉系统代理或把该域名加直连规则即可，正常应解析到 `192.168.x.x`。
- 解析正确但 502：4090 上的推理服务没起或端口映射不对。
- 报 `model not found`：`HAS_TEXT_MODEL_NAME` 与远端 id 不一致。
- 长文本被截断、日志出现 `finish_reason=length`：远端 `--ctx-size` 或 `--max-model-len` 小于
  `HAS_NER_CONTEXT_TOKENS=8192`。
